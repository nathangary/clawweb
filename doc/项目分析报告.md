## 一、项目真实全貌

本项目是伯俊智能的智能体平台前端，基于 PinchChat 二次开发，采用前后端分离架构。

### 技术栈

| 层级 | 技术 |
|------|------|
| **前端框架** | React 19 + TypeScript |
| **构建工具** | Vite 7 |
| **样式** | Tailwind CSS v4 + CSS Custom Properties |
| **图标** | Lucide React |
| **Markdown** | react-markdown + rehype-highlight + remark-gfm |
| **状态管理** | React hooks + contexts（无外部状态库） |
| **实时通信** | WebSocket（NanobotGatewayClient，端口 8787） |
| **管理 API** | REST API（NanobotApiClient，端口 18790） |

## 二、问题与缺失

### 🔴 P0 — 致命问题（不做就称不上"企业级"）

#### 1. 规则系统存在 localStorage 里

**文件：** `src/lib/rules.ts`

- 所有规则存储在 `localStorage`（key: `pinchchat_rules`）
- 清浏览器 = 规则全丢；换设备 = 规则不存在；多用户 = 规则不共享
- 规则执行引擎不存在——规则只是被生成了，但没有执行机制
- 监控面板（`AgentOrchestratorPage.tsx:334-340`）的数据是硬编码的静态数字

**影响：** 企业数据不能存在浏览器，这是架构级缺陷。

#### 2. 监控面板数据是硬编码的

**文件：** `src/components/AgentOrchestrator/AgentOrchestratorPage.tsx`

```tsx
// 第 336-338 行 — 硬编码的监控数据
<div className="text-2xl font-semibold text-pc-text">2</div>    // 活跃规则
<div className="text-2xl font-semibold text-pc-text">180</div>  // 总执行次数
<div className="text-2xl font-semibold text-pc-text">98.5%</div> // 成功率
```

**影响：** 监控面板没有实际价值。

#### 3. Dashboard 系统健康状态是写死的

**文件：** `src/components/Dashboard/DashboardOverview.tsx`

```tsx
// 第 40-45 行 — 硬编码的健康状态
const systemHealth = [
  { name: 'API服务', status: 'healthy', icon: Server },
  { name: '数据库', status: 'healthy', icon: Database },
  { name: 'Cron调度', status: runningCrons > 0 ? 'healthy' : 'idle', icon: Clock },
  { name: 'Agent引擎', status: 'healthy', icon: Cpu },
];
```

**影响：** 健康检查形同虚设。

### 🟡 P1 — 重要缺失（影响产品完整性）

#### 4. 没有用户体系和权限

- 认证只是输入网关 URL + Token，没有用户注册/登录/权限
- 没有 RBAC（角色权限控制）
- 没有多租户在前端的体现（后端通过容器隔离租户，但前端没有租户切换、数据隔离的 UI）

#### 5. 状态管理混乱

- 没有 Zustand/Redux/Jotai，全靠 `useState` + `useRef`
- `useGateway` 一个 hook 承担了认证、消息、会话、重连等所有逻辑（400 行）
- 多个组件之间存在重复的状态逻辑

#### 6. 前端缺少错误边界

- `main.tsx` 有 `ErrorBoundary`，但组件级别没有
- API 请求失败的处理非常粗糙（大部分是 `catch { setMessages([]) }`）
- 没有重试机制、没有降级策略

#### 7. 技能编排的流程图不可交互

- `FlowGraphView` 只是简单地把节点从左到右排列
- 没有拖拽、没有连线编辑、没有节点配置
- 条件分支的展示是静态的，无法可视化编辑

#### 8. 数据可视化太简陋

- 任务执行趋势图是用 CSS `div` 高度模拟的柱状图
- 没有专业的图表库（ECharts、Recharts 等）
- 没有实时数据刷新机制

---

### 🟢 P2 — 体验优化（锦上添花）

#### 9. 缺少骨架屏和加载状态优化

- 大部分加载状态是简单的 "Loading..." 文字
- 没有骨架屏（Skeleton）

#### 10. 没有性能监控

- 没有 Sentry、Web Vitals、用户行为埋点

#### 11. 国际化不完整

- 只有 en/fr，缺少中文（zh）
- UI 中有大量硬编码中文，未通过 i18n 系统管理
