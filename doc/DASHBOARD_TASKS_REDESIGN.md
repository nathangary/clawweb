# Dashboard 目标/任务界面重建设计文档

## 一、现有问题诊断

### 1.1 核心痛点
- **状态推断不准确**：当前用 `enabled` 和 `last_status` 硬编码映射到看板四列（待办/进行中/已完成/阻塞），但 CronJob 的真实状态远比这复杂——有调度周期、执行历史、成功率等多维度信息被忽略
- **全链路可视化为空谈**：所谓"全链路状态"应该展示任务从触发→执行→结果→下次调度的完整生命周期，但现在只有零散的时间戳和状态文字
- **信息架构混乱**：看板布局适合人工流转的任务，但 CronJob 是自动调度的定时任务，用看板是范式错误
- **日志可读性差**：`ExecutionChain` 组件把消息截断到 50 字符，用单字母标识角色（U/A/T），完全没有展现执行链路的因果关系

### 1.2 设计层面
- 卡片视觉层次不清晰，重要信息（下次执行时间、成功率）与次要信息平铺
- 缺少全局视角的任务健康度概览
- 无搜索、筛选、排序能力

---

## 二、设计目标

### 2.1 核心原则
1. **从"看板"转为"任务控制中心"**：定时任务不需要拖拽流转，需要的是调度监控、执行追踪、异常告警
2. **全链路 = 时间线**：每个任务的执行历史应该以时间线形式呈现，清晰展示触发条件、执行过程、结果输出
3. **异常优先**：失败/阻塞的任务应该第一时间被注意到，而不是淹没在列表中

### 2.2 信息架构

```
┌─────────────────────────────────────────────────────────┐
│  任务总览（统计卡片行）                                    │
│  [总任务数] [运行中] [下次执行<5min] [24h失败率]          │
├─────────────────────────────────────────────────────────┤
│  筛选栏 [全部/活跃/已暂停] [搜索] [排序: 名称/下次执行]   │
├─────────────────────────────────────────────────────────┤
│  任务列表（紧凑卡片列表）                                  │
│  ┌──────────────────────────────────────────────────┐   │
│  │ ▶ Daily Report    ● 活跃  │ 0 2 * * * │ 12min后  │   │
│  │   上次: 2h前 ✓    成功率 98% │ 执行 156次         │   │
│  └──────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│  任务详情面板（点击展开/侧滑）                            │
│  ├── 基本信息（名称、调度规则、创建时间）                  │
│  ├── 执行时间线（最近N次执行的完整链路）                   │
│  │    ├── [14:00] 触发 → 会话创建 → 消息发送 → 完成 ✓    │
│  │    ├── [13:00] 触发 → 会话创建 → 工具调用 → 完成 ✓    │
│  │    └── [12:00] 触发 → 会话创建 → 超时 ✗               │
│  └── 操作区（启用/暂停、删除、查看日志）                    │
└─────────────────────────────────────────────────────────┘
```

## 三、详细设计

### 3.1 任务列表（主视图）

#### 布局
- 采用**紧凑卡片列表**而非看板，每个任务一行
- 每行展示关键信息：名称、状态指示灯、Cron 表达式、下次执行倒计时、上次执行结果、成功率

#### 状态指示灯
| 状态 | 颜色 | 条件 |
|------|------|------|
| 运行中 | 绿色脉冲 | `enabled && next_run_at` 存在 |
| 已暂停 | 灰色 | `!enabled` |
| 执行中 | 蓝色脉冲 | 当前有活跃会话（需关联 session） |
| 最近失败 | 红色闪烁 | `last_status === 'error'` |
| 即将执行 | 黄色 | `next_run_at` 在 5 分钟内 |

#### 排序与筛选
- 默认按下次执行时间升序（最近的排前面）
- 筛选：全部 / 活跃 / 已暂停 / 最近失败
- 搜索：按任务名称过滤

### 3.2 任务详情面板

点击任务卡片后从右侧滑出面板（宽度 480px），包含：

#### Tab 1: 概览（只读）
- 任务名称、ID
- 调度规则可视化（Cron 表达式 + 人类可读描述，如"每小时整点"）
- 统计卡片：总执行次数、成功率、平均执行时长、连续成功次数
- 快捷操作：启用/暂停、删除

#### Tab 2: 执行时间线（核心）
- 按时间倒序展示最近 20 次执行记录
- 每次执行是一个**可展开的时间线节点**：
  ```
  ──● 2024-01-15 14:00:00  ✓ 完成 (23s)
    ├── 触发: Cron 调度
    ├── 会话: abc123
    ├── 消息: "生成日报..."
    └── 结果: 3 条消息, 1 次工具调用
  ```
- 失败的节点默认展开显示错误信息

#### Tab 3: 执行日志
- 保留现有的 `ExecutionChain` 但大幅改进
- 按 request_id 分组，展示完整的消息交互
- 工具调用可展开查看输入/输出
- 支持复制原始日志

### 3.3 空状态
- 无任务时展示引导插图 + "暂无任务"提示
- 无搜索结果时展示"未找到匹配的任务"

## 四、技术实现方案

### 4.1 组件拆分

```
DashboardTasks/
├── index.tsx              # 主容器，管理状态和筛选逻辑
├── TaskList.tsx           # 任务列表组件
├── TaskRow.tsx            # 单行任务卡片
├── TaskDetailPanel.tsx    # 右侧详情面板
│   ├── OverviewTab.tsx    # 概览 Tab
│   ├── TimelineTab.tsx    # 执行时间线 Tab
│   └── LogsTab.tsx        # 原始日志 Tab
├── TaskFilters.tsx        # 筛选栏
├── ExecutionTimeline.tsx  # 执行时间线组件
└── utils.ts               # 工具函数（状态计算、Cron解析等）
```

### 4.2 状态管理
- 筛选状态（filter、search、sortBy）用本地 state
- 选中任务 ID 用 state，控制详情面板展开
- 日志数据按需加载，缓存到 `cronLogs` 中

### 4.3 新增工具函数

```typescript

function getTaskHealth(job: CronJob): TaskHealth {
  // 返回: status, nextRunIn, lastRunAgo, successRate, consecutiveSuccess
}

// Cron 表达式转人类可读
function cronToHuman(expr: string): string {
  // "0 * * * *" → "每小时整点"
  // "0 9 * * 1" → "每周一 09:00"
}

// 计算下次 N 次执行时间
function getNextRuns(expr: string, tz: string, n: number): Date[]
```

### 4.4 样式规范
- 延续项目现有的深色主题（`bg-[#0a0a0f]` 系列）
- 状态色：emerald（成功）、red（失败）、amber（警告）、cyan（执行中）、slate（暂停）
- 卡片圆角统一 `rounded-xl`
- 动画：详情面板用 `transition-transform` 滑入，状态指示灯用 `animate-pulse`

## 五、数据流

```
DashboardPage (已有)
  └── useDashboardPage hook (已有)
        ├── cronJobs: CronJob[]     → TaskList
        ├── cronLogs: Record<>      → TimelineTab / LogsTab
        ├── onDelete                → 删除操作
        └── onFetchLogs             → TimelineTab (按需加载)
```

**不需要修改后端 API**，所有改进在前端完成。
